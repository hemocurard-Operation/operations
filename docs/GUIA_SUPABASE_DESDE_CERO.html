2. Crear o identificar el proyecto Supabase

1

Crear proyecto

Entre a Supabase y cree un proyecto nuevo para HemoCura, o abra el proyecto existente que utilizará la aplicación.

  • Nombre del proyecto identificado.
  • Región seleccionada.
  • Contraseña de base de datos guardada en un gestor seguro.
  • Proyecto terminó de aprovisionarse.
No coloque la contraseña de base de datos en GitHub.

3. Obtener Project URL y Publishable Key

2

Usar la clave correcta para navegador

En el Dashboard de Supabase, abra Connect o Settings → API Keys. Copie:

  • Project URL: https://xxxxxxxx.supabase.co
  • Publishable Key: sb_publishable_...
Para GitHub Pages use la Publishable Key. Es pública por diseño y queda limitada por RLS.
Nunca use sb_secret_..., service_role ni una Secret Key en el navegador.

Abrir ejemplo de config.js

4. Instalar la base HemoCura

3

SQL Editor

Abra SQL Editor en Supabase. Para una base nueva, ejecute:

Abrir 00_IMPLEMENT_SUPABASE_ALL_FIXED_v7_2.sql

No lo ejecute repetidamente sobre una base ya instalada. Si la ejecución se interrumpe, primero determine hasta qué punto llegó.

Qué debe sembrar automáticamente

ObjetoEsperado
Sucursales3: STI Santiago, POP Puerto Plata, TEN Tenares
Roles9

Después ejecute:

Abrir 21_VERIFY_SUPABASE_INSTALL.sql

5. Crear el primer usuario de HemoCura

4

Authentication → Users

En Supabase vaya a Authentication → Users. Cree o invite al usuario inicial y copie su User UUID.

Crear un usuario en Auth no crea automáticamente un registro en public.profiles en esta arquitectura.

7. Entender RLS antes de probar

6

La Publishable Key identifica al frontend. Después del login, Supabase aplica Auth + grants + RLS.

current_branch_id()
has_role(role_code)
can_access_branch(target_branch)
No “solucione” un error RLS colocando una Secret Key en el frontend.

8. Configurar GitHub Pages

7

Archivo único a modificar

Abrir config.example.js

En GitHub debe editar operations/js/config.js y dejar:

export const CONFIG = {
  SUPABASE_URL: 'https://TU-REFERENCIA-REAL.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'sb_publishable_TU_CLAVE_REAL',
  APP_BASE: '/operations/'
};
La Publishable Key puede estar en el navegador; la seguridad depende de Auth, grants y RLS.

Abrir status.html después del commit

11. Rutina recomendada

Antes de cambiar:
1. Identificar objeto exacto.
2. Guardar SQL actual / backup.
3. Definir cambio.
4. Validar RLS/grants.
5. Ejecutar cambio puntual.
6. Probar en SQL Editor.
7. Probar con usuario real.
8. Ejecutar #qa.
9. Documentar.
10. No tocar módulos no relacionados.
Estándar HemoCura: un problema → un objeto → una corrección → una prueba → una evidencia.
