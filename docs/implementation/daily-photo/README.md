# Reporte diario desde fotografías · v0.64.0

En Reporte Operativo Diario se puede seleccionar una imagen JPG, PNG o WebP de hasta 5 MB y 16 megapíxeles, orientarla y ejecutar el OCR local. Reutiliza los modelos españoles y licencias Tesseract ya alojados en el sitio. No envía imágenes a un servicio de IA ni guarda el texto OCR en el servidor. El lector de cédulas comparte el motor sin cambiar sus reglas de interpretación.

La lectura propone únicamente filas completas de dos cantidades bajo el encabezado Unidades disponibles: sangre total y paquete globular. Se exige comprobar fecha, sucursal y cantidades antes de aplicar al borrador. Una fila incompleta, duplicada o sin encabezado no se infiere. Una casilla vacía no modifica el valor existente; un cero escrito explícitamente sí puede aplicarse. La fecha detectada nunca cambia automáticamente el contexto del reporte. La escritura manuscrita puede no reconocerse: se debe contrastar con la foto y completar manualmente. Donantes, equipos, tamizaje y despachos no se convierten automáticamente en registros estructurados en esta versión.

Aplicar no guarda el reporte, no registra movimientos de inventario y no libera sangre. El usuario completa los apartados habituales y guarda el borrador. Entonces se adjunta la imagen original como respaldo privado, con SHA-256, usuario, fecha y cantidades revisadas. El servidor comprueba formato básico, tamaño y correspondencia del hash. No se presenta esto como análisis antivirus ni validación clínica.

La evidencia se almacena en daily_report_photos bajo RLS: perfil activo, permiso del reporte y sucursal autorizada. Los adjuntos no tienen URL pública; el binario se consulta solo al abrir la imagen. No se permiten UPDATE/DELETE directos. Se bloquea el reporte padre durante el alta para impedir una carrera con el cierre; solo BORRADOR/REABIERTO acepta nuevos adjuntos. Un índice único por reporte y hash evita duplicar la misma foto. La imagen no se copia a logs genéricos. La migración es aditiva y no modifica registros clínicos ni saldos.

Guardar reporte y adjuntar foto son dos operaciones: si el segundo paso falla, el borrador puede haber quedado guardado. La interfaz lo indica, conserva la foto para reintento y bloquea su envío desde esa pantalla hasta adjuntarla. No se afirma atomicidad entre ambos pasos. Recargar con una foto pendiente requiere confirmación; cambiar de fecha/sucursal la descarta. Salir del módulo pierde una imagen no guardada; la advertencia de cierre de pestaña no sustituye el guardado explícito. Los permisos de servidor protegen la carga incluso si otro cliente omite la interfaz.
