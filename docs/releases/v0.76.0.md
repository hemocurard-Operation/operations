# v0.76.0 — Captura plegable de inventario

Registrar componente sanguíneo se sustituye por una lista plegable de productos y cantidades. El catálogo usa productos activos y componentes presentes en el inventario autorizado. Grupo ABO/Rh se selecciona en un solo control. Sucursal y producción se capturan una vez, con vencimiento y estados en una sección plegable. La presentación se adapta a móvil y mantiene acciones accesibles.

La cantidad despliega códigos individuales: cada unidad conserva código, origen y quantity=1. Se permiten hasta 10 filas y 50 unidades por envío. No se inventan identificadores ni se reemplaza la trazabilidad por un total agregado. Los códigos duplicados, identidades incompletas y cantidades no enteras se rechazan antes de enviar. Un único INSERT de Postgres registra el lote de forma atómica, bajo los permisos y controles existentes. Se conservan datos ante errores y se bloquea el doble envío mientras se guarda.

Valores iniciales: tamizaje PENDIENTE e inventario CUARENTENA. No se modifican reglas de liberación, RLS ni esquema. La API devuelve solo id y unit_code. Las fechas y estados compartidos se aplican a todas las unidades del envío; componentes con contexto diferente se registran en envíos separados.

Verificación: dominio, navegador con datos sintéticos para captura plegable, cantidades, códigos, fallo de guardado y envío único, ajuste móvil y regresión de navegación; sintaxis y presupuesto UX. Ninguna unidad real fue creada durante las pruebas.
